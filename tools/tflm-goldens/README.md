# tflm-goldens — executed-tflite-micro golden capture

Host-only golden-capture harness that runs the 6 zoo models through the **REAL
tflite-micro binary** (reference kernels, single-threaded) at a **pinned SHA**
and prints the executed int8 output + FNV-1a hash. This retires the provenance
debt documented in `tools/generate_goldens/README.md` and
`models/zoo/DEFERRED_MODELS.md` §6: the current model goldens were captured
from **ai-edge-litert (LiteRT)** — a *different* TFLite implementation with
double-rounding requantization — while Hematite's kernels implement TFLM's
single-rounding semantics. The harness's job is to capture what TFLM
**actually produces** so Hematite can be tested against its true spec.

## Pinned SHA (non-negotiable)

```
18b9e6f2a8c5a9518e588f59c2ba16ef7ef9d551
```

This is the TFLM spec version the golden corpus declares
(`GOLDEN_TFLM_VERSION` in every golden under `hematite-tests/goldens/`).
Verify the checkout before building:

```sh
git clone https://github.com/tensorflow/tflite-micro /tmp/tflite-micro
cd /tmp/tflite-micro && git checkout 18b9e6f2a8c5a9518e588f59c2ba16ef7ef9d551
git rev-parse HEAD   # must print 18b9e6f2a8c5a9518e588f59c2ba16ef7ef9d551
```

The clone lives **outside this repo** (e.g. `/tmp/tflite-micro` or
`~/tflite-micro`) — the tflite-micro tree is deliberately NOT vendored here
(it is huge); the harness only references it via `TFLM_ROOT`.

> **Build-system note:** the pinned SHA has no CMake support (removed
> upstream). The supported build path at this SHA is the upstream Makefile
> build, which this directory's `Makefile` wraps. There is deliberately no
> `CMakeLists.txt` here — it would have nothing to call into.

## Layout

| File | Role |
|---|---|
| `extract_inputs.py` | Parses `hematite-tests/goldens/models/*.rs` — single source of truth — and emits `generated/<stem>.bin` (raw i8 input bytes, **byte-identical** to the Rust `INPUT_DATA` arrays), `generated/manifest.json`, `generated/cases.inc` (the model table `main.cc` compiles in), `generated/golden_hashes.json`. Also emits a 7th case: the `hard_swish` op fixture's INPUT_DATA (from `goldens/hard_swish.rs`) run through the committed hard_swish micro-model |
| `generate_hard_swish_model.py` | Deterministic flatbuffers builder for `models/hard_swish_int8.tflite` — a minimal int8 HardSwish-only micro-model (scale 1.0 / zero-point 0 both sides), committed (472 bytes); consumed by the 7th case |
| `main.cc` | C++ harness: `tflite::MicroInterpreter` + `MicroMutableOpResolver` (reference kernels via `TF_LITE_DISABLE_X86_NEON`), loads each model, runs inference on the `.bin` input, prints the output tensor as a comma-separated i8 array + FNV-1a 32-bit hash |
| `Makefile` | Extracts inputs, builds `libtensorflow-microlite.a` at the pinned SHA (via upstream make), compiles/links `main.cc` |

The 7 cases: the 6 models `models/sine.tflite`,
`models/zoo/sine_regression/hello_world_int8.tflite`,
`models/zoo/keyword_spotting/kws_micro_speech_int8.tflite`,
`models/zoo/anomaly_detect/anomaly_detect_int8.tflite`,
`models/zoo/person_detect_vww/person_detect_int8.tflite`,
`models/zoo/mobilenetv2_cls/mobilenet_v2_1.0_224_int8.tflite`
plus `models/hard_swish_int8.tflite` (the hard_swish op case).

## Build & run

```sh
# 1. Clone + checkout tflite-micro at the pinned SHA (outside this repo)
git clone https://github.com/tensorflow/tflite-micro /tmp/tflite-micro
cd /tmp/tflite-micro && git checkout 18b9e6f2a8c5a9518e588f59c2ba16ef7ef9d551

# 2. Build + run (TFLM_ROOT defaults to /tmp/tflite-micro; override if needed)
make TFLM_ROOT=/tmp/tflite-micro run
```

First build downloads third-party deps (flatbuffers, gemmlowp, ruy, kissfft)
into the tflite-micro tree and compiles ~500 sources — allow several minutes.
`make` re-verifies the checkout SHA before building. `make inputs` alone
re-extracts the `.bin` inputs.

## Determinism & byte-identical inputs (the critical constraint)

- Inputs are derived **only** from the `INPUT_DATA` arrays in the Rust goldens
  (which are zero-point-filled neutral inputs captured by
  `tools/generate_goldens/zoo/run_model.py`). If the harness input differs
  from the golden input by one byte, the captured golden is wrong.
- `extract_inputs.py` is deterministic and re-runnable; `generated/` is
  gitignored and regenerated by `make inputs`.
- Harness + library build with no optimization flags (library uses upstream
  defaults; harness compiles `-O0`); single-threaded; reference kernels only.

## Output format (consumed by the golden generator)

```
== MODEL <name> ==
input_shape: 1 1960
output_shape: 1 4
output: -64,-64,-64,-64
fnv1a: 0x3a24ca75 (975504501)
```

FNV-1a is 32-bit, seed `2166136261`, prime `16777619`, over the raw output
bytes (i8 → u8) — identical to `hematite-benchmarks/src/model_validation.rs`.

## Regenerating goldens from harness output (todo T10)

```sh
make TFLM_ROOT=/tmp/tflite-micro run > generated/harness_output.txt
cargo run -p generate-goldens -- tflm-regen generated/harness_output.txt
```

The generator (1) cross-checks the FNV-1a printed per case against a
recompute, (2) rewrites model goldens whose executed-TFLM hash differs from
the current golden (`anomaly_detect_int8`, `mobilenet_v2_1.0_224_int8` —
values from the harness output VERBATIM; the other 4 models match and are
left untouched), and (3) re-tiers the `hard_swish` op fixture from the
DOWNGRADED integer-rational approximation to executed-TFLM HardSwish output.
All regenerated files carry a `GOLDEN_PROVENANCE` recording the pinned SHA,
date, and generation command.

## Sanity gate (MUST pass before goldens may be regenerated — todo T10)

`kws_micro_speech_int8` is already bit-exact between LiteRT (the current
golden source) and Hematite, so executed TFLM must reproduce it too. Running
the harness must print:

```
== MODEL kws_micro_speech_int8 ==
output: -64,-64,-64,-64
fnv1a: 0xbb84c615 (3146040853)
```

matching `hematite-tests/goldens/models/kws_micro_speech_int8.rs`
(`EXPECTED_OUTPUT = [-64, -64, -64, -64]`). This validates the entire
harness + input pipeline. The other 5 models may legitimately differ from the
current (LiteRT-derived) goldens — those differences are the point (see
`models/zoo/DEFERRED_MODELS.md` §6) and are reconciled in todo T10, which
regenerates goldens from THIS harness's output.
